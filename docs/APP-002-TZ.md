**Дата:** 08.09.2026

**APP-ID:** APP-002  
**DATA MODE:** CLOUD DATA — Supabase MINI-APPS-CLOUD  
**GitHub:** `setjip-spec/vr-catalog`  
**Live:** `https://setjip-spec.github.io/vr-catalog/`

## 1. Назначение

VR Catalog — личное мини-приложение для Meta Quest 3 / PCVR. Оно должно быстро отвечать на вопросы: во что играть, что установить, где лучше запускать, что уже пробовал, что стоит купить и какие программы реально полезны.

Каталог не должен превращаться в полный дамп магазинов или QLoader. Цель — **отборная библиотека**, где остаются только достойные позиции.

## 2. Источник истины и архитектура

- GitHub `main` — канонический код и статический каталог.
- GitHub Pages — единственный нормальный пользовательский Web-runtime.
- Supabase `MINI-APPS-CLOUD` — авторизация и персональное состояние APP-002.
- `localStorage` — быстрый кэш и аварийный слой, не единственный источник пользовательских данных.
- Google Drive BACKUP SAFE — независимая disaster-recovery копия.
- Orbikon не трогать без отдельного указания.

Статические записи хранятся в `data-*.js`. Персональные статусы, комментарии, виды, фильтры, выбранные колонки и сортировка синхронизируются через Supabase.

## 3. Типы записей

Каталог поддерживает четыре независимых типа:

1. **Игра** — обычная VR/MR-игра.
2. **Программа** — браузер, видеоплеер, PCVR-клиент, файловый менеджер, системная утилита, рабочий стол и т. п.
3. **Мод / инструмент** — UEVR, REFramework, Flat2VR и подобные инструменты.
4. **18+** — отдельный тип для небольшого отобранного adult VR/MR-каталога. Не смешивать его с обычными играми и программами.

Фильтр `Тип` должен позволять мгновенно скрыть/показать каждую группу отдельно.

## 5. Рейтинг

`rating` — **редакционная оценка каталога 0–10**, а не буквальное копирование одного магазина.

Она учитывает:

- качество игры/программы;
- качество VR-механик;
- пользовательские отзывы;
- профильные VR-обзоры;
- популярность и долговечность проекта;
- актуальность на Quest 3;
- качество конкретной Quest/PCVR-версии;
- удобство и ценность именно для этого каталога.

Нельзя занижать позицию только потому, что её нет в одном конкретном топе. Для включения достаточно хотя бы одного сильного сигнала: **высокий пользовательский рейтинг ИЛИ сильные отзывы профильных VR-изданий ИЛИ заметная популярность/качество**.

## 6. QLoader — импорт v1

Исходная выгрузка QLoader: **3575 релизов / 3513 уникальных названий**.

Это справочник кандидатов, а не список для автоматического импорта.

Правила:

- не начинать подбор с нуля;
- уже принятые сильные позиции считать базой;
- искать только недостающие качественные игры и программы;
- не добавлять мусор, короткие технодемо, заброшенные проекты и десятки клонов;
- если есть улучшенная версия для Quest 3 — учитывать её;
- если в QLoader известна RUS-версия — отдавать ей предпочтение и фиксировать это в `qloader`;
- статическую базу расширять отдельными `data-*.js`, не ломая существующие пользовательские ID.

Приоритет отбора:

Не добавлять ради количества:

- маленькие демки;
- технические samples;
- почти одинаковые приложения;
- заброшенные проекты.

`XRI Sample` не считать 18+ приложением.

## 10. Платформа и доступность

Базовые значения:

- Только Meta;
- Только Steam;
- Meta + Steam;
- Meta + Steam скоро;
- Программа;
- специальные значения для standalone/sideload/PCVR, если обычные варианты искажают смысл.

Фильтр `Доступность` обязан включать реальные значения, присутствующие в данных, а также макросы:

- Есть в Meta;
- Есть в Steam.

`Где лучше` — отдельное поле: Steam лучше / Meta лучше / Равно / —.

## 11. Steam vs Meta

Steam/PCVR выше, когда важны графика, текстуры, моды, крупная сюжетная игра и возможности ПК.

Meta/Quest выше, когда важны минимальная задержка, автономность, быстрый запуск, ритм/фитнес, room-scale или mixed reality.

## 12. Комфорт

Комфорт/укачивание остаётся важным свойством. Использовать понятные значения вроде:

- Стою на месте;
- Очень комфортно;
- Низкий риск;
- Средний риск;
- Высокий риск.

Не скрывать высокий риск у быстрых smooth-locomotion, полётов и активного паркура.

## 16. Supabase

Архитектура персонального слоя:

`GitHub Pages → Supabase Auth → mini_app_state(APP-002)`.

В Supabase сохраняются пользовательские изменения, но **статический справочник игр/программ/18+ остаётся в GitHub** и не дублируется туда без отдельной причины.

Обычная фильтрация, сортировка и ввод должны быть мгновенными. Синхронизация идёт асинхронно.

После F5 и на телефоне под тем же аккаунтом пользовательские изменения должны сохраняться.

## 17. Безопасность

- service_role / secret key никогда не помещать во frontend;
- publishable key допустим только вместе с корректным RLS;
- не сбрасывать пользовательские edits при расширении статического каталога;
- новые записи получают новые стабильные ID;
- существующие ID не переиспользовать.

## 18. GitHub workflow

Работать только от текущего `main`.

Порядок изменения поведения:

1. обновить это ТЗ;
2. изменить код/данные;
3. выполнить syntax/CI checks;
4. дождаться GitHub Pages;
5. проверить live;
6. сделать BACKUP SAFE на существенном milestone.
